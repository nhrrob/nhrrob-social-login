# 2026-11-24

## Where things stood

0.1.0, private, not on WordPress.org. Settings → Social Login was a classic
Settings API screen. Open issues: #1 (Settings link), #2 (React screen), #4
(decision log). No paid add-on was planned.

## What was done

- 0.2.0: Settings → Social Login is a React app (`admin/src`, built into
  `admin/build`) with the shell, colours and dark mode of NHR Issue Reporter.
  It reads and saves through `GET`/`POST nhrrob-social-login/v1/settings`
  (`manage_options`); the secret never comes back, only whether one is set.
- A Settings link on the Plugins screen (#1), this decision log (#4).
- Hooks for an add-on: `nhrrob_social_login_signed_in`, `nhrrob_social_login_enqueue`
  and the `nhrrobSocialLogin.app` JS filter.
- Checked on the dev site in Playwright: the screen in light and dark at
  1280px and 390px (no horizontal scroll, no console errors), saving, the
  button at the top of the login form, and a whole sign-in from a comment
  form against a stand-in for Google's token endpoint: back on the post,
  logged in as a new Subscriber, the hook fired with `created: true`.

## WordPress.org prep (`wporg-prep`)

- Plugin Check clean on the files the zip holds (`wp plugin check` with low
  severity and experimental checks), and a `plugin-check.yml` workflow.
- Hand releases and the two 10up deploy workflows, from Post Insights;
  `release.yml` removed.
- `readme.txt`: five tags, Installation, a source FAQ and Screenshots.
- `.wordpress-org/`: icon and banners from `docs/wporg/`, four screenshots
  from the dev site (login form, comment form, the screen in light and dark).
- `uninstall.php` also removes sign-ins in progress (transients).
- `.gitattributes` and `.distignore` leave out docs, tests and dev files, and
  keep `package.json` and `admin/src`.

## Release on a tag

- The tag push now also makes the GitHub release (a second job in
  `deploy-on-pushing-a-new-tag.yml`), so a release is only `git tag` and
  `git push` of the tag. Robin's request, the same in every plugin.

## Hooks for the Pro newsletter sync

- 0.3.0 adds two filters for add-ons: `nhrrob_social_login_button_extra`
  (markup after the button, kept to labels, checkboxes and spans) and
  `nhrrob_social_login_start_data` (data kept through a sign-in, passed to
  `nhrrob_social_login_signed_in` as `data`). The paid add-on's newsletter
  opt-in uses both. Made in a separate worktree while other work went on in
  this checkout.
