# 2026-11-24

## Where things stood

0.1.0, private, not on WordPress.org. Settings → Social Login was a classic
Settings API screen. Open issues: #1 (Settings link), #2 (React screen), #4
(decision log). No paid add-on was planned.

## What was done

- 0.2.0: Settings → Social Login is a React app (`admin/src`, built into
  `admin/build`) with the shell, colours and dark mode of NHR Issue Reporter.
  It reads and saves through `GET`/`POST nhrrob-social-login/v1/settings`
  (`manage_options`); the secret never comes back, only whether one is set.
- A Settings link on the Plugins screen (#1), this decision log (#4).
- Hooks for an add-on: `nhrrob_social_login_signed_in`, `nhrrob_social_login_enqueue`
  and the `nhrrobSocialLogin.app` JS filter.
- Checked on the dev site in Playwright: the screen in light and dark at
  1280px and 390px (no horizontal scroll, no console errors), saving, the
  button at the top of the login form, and a whole sign-in from a comment
  form against a stand-in for Google's token endpoint: back on the post,
  logged in as a new Subscriber, the hook fired with `created: true`.
